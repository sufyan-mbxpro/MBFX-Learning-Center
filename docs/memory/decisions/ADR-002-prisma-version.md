# ADR-002: Build on Prisma 7.10.x, not Prisma 8

**Status:** Accepted
**Date:** 2026-08-31
**Module:** 00 — Repo scaffold & governance (Day-1 decision per plan.md Part F #2)
**Supersedes:** —
**Superseded by:** —

## Context

`plan.md` Part F #2 left the Prisma major version OPEN with an explicit
instruction: check Prisma 8's GA/stability on Day 1 and use "the stable
production-ready line". Part A1 recorded that Prisma 8 was "at/near GA".

Day-1 registry check (2026-08-31):

| Package          | `latest` dist-tag | Notes                     |
| ---------------- | ----------------- | ------------------------- |
| `prisma` (CLI)   | `8.0.0-rc.12`     | still a release candidate |
| `@prisma/client` | `7.10.0`          | stable; `prev` = 6.19.3   |

The CLI's `latest` tag pointing at an RC while the client's `latest` points at
7.10.0 means an unpinned install would produce a **split CLI/client major**,
which is exactly the kind of skew that produces confusing generate-time errors.

## Decision

Pin **Prisma 7.10.x** for both `prisma` and `@prisma/client`, with the version
recorded in `docs/memory/stack.md`. Do not install `prisma@latest` unpinned —
that resolves to the 8.x RC.

Prisma 7's breaking changes from 6 still apply and are adopted as planned
(Part A4): `prisma-client` generator with a required custom `output`
(`packages/db/src/generated/client`), `prisma.config.ts` replacing the
package.json `"prisma"` block, the `@prisma/adapter-mariadb` driver adapter,
and removal of `relationMode = "prisma"` in favor of real foreign keys.

Revisit after Prisma 8.0 reaches GA. The upgrade is contained to
`packages/db` because every other package imports the client through that
package's singleton re-export.

## Consequences

- We forgo Prisma 8 features and whatever performance work landed in that line.
- We avoid shipping a production data layer on an RC, and avoid a CLI/client
  major mismatch.
- `turbo.json`'s `@repo/db#generate` outputs must point at the custom output
  directory (`src/generated/client/**`), not `node_modules/.prisma/**` — the
  v6-era path. This is already reflected in the scaffold.
- The generated client is gitignored and regenerated by the `generate` task,
  so a stale checkout cannot silently typecheck against an old schema.

## Alternatives considered

- **Prisma 8 RC now.** Rejected: "stable production-ready line" was the stated
  test and an RC fails it. The cost of migrating 7→8 later is bounded to one
  package; the cost of an RC bug in the data layer during Phase 0–1 is not.
- **Stay on Prisma 6.** Rejected: 6 is already superseded, and 7's driver
  adapters and real-FK posture are improvements the plan explicitly wants.

## Compliance

- Exact versions pinned in `docs/memory/stack.md`; `packages/db/package.json`
  uses an exact `7.x` pin rather than a floating range that could cross a major.
- Module 01's DoD (`pnpm db:reset && pnpm db:seed && pnpm db:seed` green)
  exercises the chosen line end to end.
