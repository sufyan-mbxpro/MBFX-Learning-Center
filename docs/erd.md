# Schema ERD — `@repo/db`

Generated by hand from `packages/db/prisma/schema.prisma` (Module 01). Split
by domain rather than one 30-entity diagram — update alongside the schema,
it isn't generated in CI. Field lists are trimmed to keys, FKs, and anything
that shapes a relationship; see the schema file for the full column list.

## Identity & Auth

`User`/`Account`/`Session`/`Verification`/`TwoFactor` are Better Auth's
generated shape (ADR-001) merged with project fields — see the schema
file's comment block for provenance.

```mermaid
erDiagram
  User ||--o{ Account : "accounts"
  User ||--o{ Session : "sessions"
  User ||--o{ TwoFactor : "twofactors"
  User ||--o{ UserRole : "roles"
  User ||--o{ UserPermission : "permissions"
  User ||--o| Employee : "employee"
  User ||--o{ AuditLog : "auditLogs"

  User {
    string id PK
    string email UK
    string name
    UserType userType
    UserStatus status
    boolean deletedAt
  }
  Account {
    string id PK
    string userId FK
    string issuer
    string accountId
    string password "credential provider only"
  }
  Session {
    string id PK
    string userId FK
    string token UK
    string impersonatedBy
  }
  Verification {
    string id PK
    string identifier "not user-FK'd"
    string value
  }
  TwoFactor {
    string id PK
    string userId FK
    string secret
    string backupCodes
  }
```

## RBAC

Deny beats allow, deny beats super_admin (`.claude/rules/security.md` #2) —
enforced in `@repo/rbac` (Module 03), not by this schema.

```mermaid
erDiagram
  Role ||--o{ RolePermission : "permissions"
  Permission ||--o{ RolePermission : "roles"
  RolePermission }o--|| Role : "roleId"
  RolePermission }o--|| Permission : "permissionId"

  User ||--o{ UserRole : "roles"
  Role ||--o{ UserRole : "users"

  User ||--o{ UserPermission : "permissions"
  Permission ||--o{ UserPermission : "users"

  Role {
    string id PK
    string key UK
    int level "escalation guard"
    boolean isSystem
  }
  Permission {
    string id PK
    string key UK "resource.action"
    string groupName
  }
  UserPermission {
    string userId FK
    string permissionId FK
    PermissionEffect effect "ALLOW default, DENY overrides"
  }
```

## Employees

Distinct from auth identity — `Employee.userId` is nullable (HR record can
predate a login).

```mermaid
erDiagram
  Department ||--o{ Employee : "employees"
  Designation ||--o{ Employee : "employees"
  Employee ||--o{ Employee : "directReports (self, reportingToId)"
  User ||--o| Employee : "employee"

    string id PK
    string userId FK "nullable, unique"
    string employeeCode UK
    string workEmail UK

```

## Settings, Feature Flags, Theming, Branding

`Setting.value`/`FeatureFlag` drive runtime config (`@repo/settings`, Module
05); `Theme` drives `@repo/theme`'s CSS variable derivation (Module 02).
`Theme.allowUserToggle` intentionally does not exist (plan.md A5.4, ADR-008).

```mermaid
erDiagram
  Setting {
    string id PK
    string key UK
    json value
    boolean isPublic "never serialize to public RSC if false (security.md #12)"
  }
  FeatureFlag {
    string id PK
    string key UK
    boolean isEnabled
    FeatureVisibility visibility
  }
  SocialLink {
    string id PK
    string platform UK
    string icon "built-in glyph key (ADR-045)"
    string iconUrl "admin-uploaded, nullable, WINS over icon"
  }
  Theme {
    string id PK
    string key UK
    json brandColors
    json lightSurface
    json darkSurface
    json darkBrandOverrides
    boolean isActive
    string scope "web | admin | both"
  }
  BrandAsset {
    string id PK
    string key UK "logo_light | logo_dark | favicon | og_image"
  }
```

## Articles — News & Analysis (Module 15, ADR-015; extended changes-07 PR 2)

One `Article` base row + `kind` (NEWS / ANALYSIS / TRADE_IDEA), with the
base+translation pattern above. Related posts are **not** a column: they are
`ContentRelation` rows (`sourceType "article"`, `relationType "related"`),
reusing the generic linking table. FAQ entries hang off the TRANSLATION, not
the article — a question and its answer are translatable prose, so they are
per-locale by construction and cascade with the translation.

```mermaid
erDiagram
  Article ||--o{ ArticleTranslation : "translations"
  Article ||--o{ ArticleTagAssignment : "tags"
  Article }o--|| ArticleCategory : "category"
  ArticleTranslation ||--o{ ArticleFaqItem : "faqItems"
  ArticleTag ||--o{ ArticleTagAssignment : "articles"

  Article {
    string id PK
    ArticleKind kind
    ContentStatus status
    boolean isActive "instant hide/show, status untouched"
    boolean isPremium "ADR-012, unenforced"
    boolean isFeatured "changes-07: editorial promotion"
    string coverImageUrl "card/OG image"
    string coverImageAssetId "ADR-035 usage guard"
    string headerImageUrl "changes-07: top of THIS article's page"
    string headerImageAssetId "ADR-035 usage guard"
    string videoUrl "provider whitelist, embed derived at render"
    boolean showRelated "changes-07: render toggle"
    int relatedCount "changes-07: how many to show"
    datetime scheduledFor
    datetime publishedAt
    datetime deletedAt
  }
  ArticleTranslation {
    string articleId FK
    string locale
    string slug "unique per (locale, slug)"
    string body "sanitized HTML, ADR-009"
    string seoTitle
    string seoDescription
    string ogImageUrl
    string canonicalUrl
    boolean noIndex
    string focusKeywords "changes-07: comma-separated, parsed in @repo/utils"
    boolean noFollow "changes-07"
    string ogTitle "changes-07: null means inherit"
    string ogDescription "changes-07: null means inherit"
    string twitterCard "changes-07: summary | summary_large_image"
    string twitterImageUrl "changes-07"
    string twitterImageAssetId "changes-07, ADR-035 usage guard"
    TranslationStatus translationStatus
  }
  ArticleFaqItem {
    string id PK
    string translationId FK "cascade; per-locale by construction"
    int sortOrder
    string question
    string answer "sanitized HTML, same ADR-009 pipeline as bodies"
  }
```

## Content — base + translation pattern

Course/Module/Lesson/GlossaryTerm all follow: locale-invariant base row,
slug lives on the translation, `(locale, slug)` unique per model. Articles,
tools, and static pages follow identically once added (plan.md A7 — not
blocking Phase 0). `authorId` is a loose reference (no FK) to `User.id`.

```mermaid
erDiagram
  Course ||--o{ CourseTranslation : "translations"
  Course ||--o{ Module : "modules"
  Module ||--o{ ModuleTranslation : "translations"
  Module ||--o{ Lesson : "lessons"
  Lesson ||--o{ LessonTranslation : "translations"
  GlossaryTerm ||--o{ GlossaryTermTranslation : "translations"

  Course {
    string id PK
    ContentStatus status
    string authorId "loose ref to User.id, no FK"
    boolean deletedAt
  }
  CourseTranslation {
    string courseId FK
    string locale
    string slug "unique per (locale, slug)"
  }
  Module {
    string id PK
    string courseId FK
  }
  Lesson {
    string id PK
    string moduleId FK
    string prerequisiteLessonId "loose ref, no FK"
    boolean deletedAt
  }
  LessonTranslation {
    string lessonId FK
    string locale
    string slug "unique per (locale, slug)"
    string sourceHash "flips translationStatus to OUTDATED on source change"
  }
  GlossaryTerm {
    string id PK
    string category
  }
  GlossaryTermTranslation {
    string termId FK
    string locale
    string slug "unique per (locale, slug)"
  }

  ContentRelation {
    string sourceType "polymorphic, no FK"
    string sourceId
    string targetType
    string targetId
  }
```
